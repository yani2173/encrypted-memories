Privacy policy

Encrypted Memories is an independent, open source Proton Drive client. It has no advertising, custom analytics, or cross-app tracking.

Privacy contact

For privacy questions or requests, email privacy@oncloud.at.

How the app handles data

Your sign-in and library requests go to Proton Drive. The app processes your session, Proton Drive content and metadata, Apple Photos metadata and media covered by enabled backup features, selected macOS-folder data, and app settings to provide the features you request. Encrypted Memories does not send your Proton password, photos, or search queries to the project maintainer.

If you enable Apple Photos backup, a full backup pass can enumerate metadata for the whole Photos library. Album and macOS-folder workflows use the selections you make. Media covered by the enabled backup configuration can be uploaded to your Proton Drive account.

Smart Search runs on your device. When you turn on Smart Search, the model catalog and the model you choose download from models.oncloud.at. These requests contain no photo bytes or search text. The service receives ordinary HTTPS request metadata, and artifact requests include the app identifier.

When Map and Places is on, the app sends photo location coordinates to Apple's MapKit reverse-geocoding service to name places in the photo viewer, on the map, and in search suggestions. For search suggestions, it sends only the rounded center of a group of photos, precise to about 1 km. These requests contain no photos, filenames, or search text. Apple handles them under Apple's privacy policy.

MapKit loads map tiles from Apple for the area visible in the Map view and the small maps in photo details. If you have opened the Map view before, the app can preload its opening area at launch. These requests reveal the map region to Apple. In Settings > Privacy, turn off Map and Places to hide the Map view, stop map preloading and place lookups, and show coordinates as text in photo details. The encrypted location index remains on your device.

Analytics

The app sends no usage analytics to its developer. Apple may provide aggregate App Analytics and diagnostics when you enable sharing with app developers. Apple handles that data under Apple's privacy policy.

Storage and support

Your session is stored in the system Keychain. App-controlled caches, settings, and search indexes remain on your device until you clear them, sign out, or remove the app. Data in Proton Drive remains subject to Proton's privacy policy.

Release builds do not write file debug logs. Runtime-gated unified logging is disabled unless explicitly enabled for a local investigation. Support reports use a privacy-filtered in-memory diagnostics buffer and are generated locally on request.

A support report is generated locally. On macOS, the app asks you to save it. On iPhone and iPad, Apple's share sheet lets you choose a recipient. The interface then opens a GitHub issue page. The current report contains app, build, operating-system, runtime, resource, network, and allowlisted diagnostic values. It is designed not to contain filenames, asset identifiers, paths, search text, model input, or photo contents. Review it before sharing. GitHub or another recipient receives it only when you choose to share or submit it.

Public issues and automated triage

GitHub receives and publicly displays issues that you submit under GitHub's privacy statement. When the issue-triage workflow is configured and the issue includes the required acknowledgement, it sends deterministic redacted excerpts from the new issue and selected existing public issues to the external HTTPS model endpoint configured by the repository owner. Redaction removes common credentials, credential-bearing URLs, email addresses, and high-confidence long token strings before the request. Without the acknowledgement, the workflow skips model triage. The result is advisory and may add labels or comments. It does not close issues automatically. Do not include personal, confidential, or sensitive data in an issue.

Automated pull request review

For repository pull requests, the configured review workflow may send redacted excerpts of the public pull request title, description, changed file paths, diff code, and surrounding prose to the external HTTPS model endpoint configured by the repository owner. The workflow processes pull request data as untrusted text and never checks out or executes code from the pull request. Redaction removes common credentials, credential-bearing URLs, email addresses, and high-confidence long token strings before the request. The result is an advisory comment review only; it never approves, requests changes, merges, closes, or edits files. Do not include personal, confidential, or sensitive data in a pull request.

Website hosting

This policy site is hosted on GitHub Pages. GitHub may log and store visitor IP addresses for security. GitHub's privacy statement applies to that processing. The site contains no first-party analytics or advertising code.

Your rights

Subject to applicable conditions and exceptions, you may request access, rectification, erasure, restriction of processing, and data portability. You may also object where applicable. If processing relies on consent, you may withdraw consent at any time without affecting earlier processing. Contact privacy@oncloud.at for requests. You may also complain to the Austrian Data Protection Authority through its complaint procedure.
